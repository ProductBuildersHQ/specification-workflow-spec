# Release v0.3.0

**Release Date:** 2026-08-15

**This is the final release of specification-workflow-spec as a standalone repository.** Its content — the workflow catalog, loaders, templates, rubrics, and the tools it grew (pipelines, loops, integrations, prism-sync) — has been merged into [ProductBuildersHQ/visionspec](https://github.com/ProductBuildersHQ/visionspec), which has been renamed to **specification-workflow-spec**, taking over this repository's name and Go import path. This repository is retained under `tmp_specification-workflow-spec` as a private, archived historical record; see the merged repo's `v1.0.0` release notes for the consolidation rationale.

This release captures 17 commits of real, shipped work that accumulated after v0.2.0 without ever being tagged — closing that gap before archival.

## Highlights

- **Loader-enforced provenance**: a `SpecSource` declares which workflow owns a spec's template/rubric (or `"local"`), and a declared source that doesn't actually provide the file is a load-time error — provenance is enforced, not just documented.
- **Layered rubric schema**: `structured-evaluation`'s `RubricSet` gained `Class`/`Blocking`/`Evaluation`/`JudgeInstructions` fields, wired through the loader and regenerated JSON schemas.
- **Hardened AWS door workflows**: `aws-one-way-door` and `aws-two-way-door` (replacing the earlier product/feature-named profiles) ship normative enterprise contract templates/rubrics and symmetric optional deepening — both MRD (product scale) and OpportunitySpec (feature scale) feed PRD synthesis in both doors.
- **Loader cycle guard**: the resolution chain now threads through both `extends` links and explicit spec sources, so a source naming a descendant is caught as a circular reference instead of recursing forever.
- **prism-sync**: a nested-module tool (`tools/prism-sync`) that copies roadmap-domain templates/rubrics from `prism-roadmap` with provenance headers and a `-check` drift mode — keeping `prism-roadmap` out of the library's own module graph.
- **Catalog registries**: embedded pipeline, loop, and integration registries with a cross-reference test validating pipelines against workflows/integrations/spec-types and loops against everything.

## Installation

This is a terminal tag. Do not `go get` this module going forward — depend on
[github.com/ProductBuildersHQ/specification-workflow-spec](https://github.com/ProductBuildersHQ/specification-workflow-spec)
(the renamed former visionspec) instead, which carries this content forward
with full git history preserved via a history-preserving merge.

```bash
go get github.com/ProductBuildersHQ/specification-workflow-spec@v0.3.0
```
